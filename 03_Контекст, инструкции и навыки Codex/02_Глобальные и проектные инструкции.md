# Микроурок 8. Глобальные и проектные инструкции

## Зачем нужны постоянные инструкции

- В диалоге можно договориться о правилах работы
- Часть договорённостей может потеряться при длинной работе и сжатии контекста
- Постоянные правила можно вынести в `AGENTS.md`
- Codex получает эти инструкции при работе с проектом

## Два уровня инструкций

### Глобальные инструкции

- **Действуют во всех проектах**
- Подходят для общих правил работы
  - как общаться с пользователем
  - как объяснять сложные вещи
  - как обращаться с файлами
  - когда спрашивать разрешение

### Проектные инструкции

- **Действуют только внутри конкретного проекта**
- Учитывают особенности именно этой работы
  - назначение проекта
  - устройство файлов
  - источники информации
  - правила выполнения задач
  - важные ограничения

### Совместная работа двух уровней

- Codex учитывает глобальные и проектные инструкции одновременно
- Глобальные правила задают **общий способ работы**
- Проектные правила уточняют его **для конкретного проекта**
- При конфликте более близкая к текущей папке инструкция имеет приоритет

## Как создать проектные инструкции

### Через обычный запрос

- Обсудить с Codex, как должна быть устроена работа
- Сформулировать основные требования
- Попросить создать `AGENTS.md` для проекта

### Через команду `/init`

- Запустить `/init` в нужном проекте
- Codex изучит проект и предложит начальные инструкции
- Получившийся файл можно проверить и дополнить

### Через предварительное обсуждение

- Сначала подробно обсудить правила в диалоге
- Попросить Codex собрать их в единый список
- Затем использовать `/init` с указанием учесть принятые решения

## Как создать глобальные инструкции

- Попросить Codex создать или обновить глобальный `AGENTS.md`
- Глобальный файл находится в папке настроек Codex
- В него выносить **только правила, которые действительно нужны во всех проектах**
- Особенности отдельного проекта оставлять в проектном `AGENTS.md`

## Инструкции и сжатие контекста

- Сжатие истории диалога **не отменяет** глобальные и проектные инструкции
- После сжатия Codex продолжает получать инструкции `AGENTS.md` **отдельно от сокращённой истории**
- Изменения в `AGENTS.md`, сделанные во время уже открытого диалога, надёжнее применять **в новом диалоге**
- Codex не перечитывает изменённый файл с диска после каждого сжатия
- Другие файлы проекта автоматически после сжатия не перечитываются
  - `PROJECT.md`
  - `TODO.md`
  - файлы с текущим состоянием и другими знаниями проекта

## Проверка инструкций

- Попросить Codex назвать загруженные инструкции
- Проверить, какие глобальные и проектные правила он видит
- После изменения `AGENTS.md` открыть новый диалог
- Убедиться, что новые правила учитываются в работе

## Основной принцип

- **Глобальные инструкции** — правила для всей работы с Codex
- **Проектные инструкции** — правила конкретного проекта
- **История диалога** хранит текущий разговор
- `AGENTS.md` хранит постоянные правила поведения Codex
