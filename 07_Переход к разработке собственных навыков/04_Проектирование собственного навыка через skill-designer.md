# Микроурок 20. Проектирование собственного навыка через `skill-designer`

## Создание файлов — не первый шаг

- Человек хочет превратить повторяющуюся работу в навык
- Первый порыв
  - сразу попросить Codex создать `SKILL.md`
- Но до создания файлов ещё нужно определить
  - какую работу выполняет навык
  - когда он должен запускаться
  - какой результат считается готовым
  - что Codex решает самостоятельно
  - какие решения остаются за человеком
- Если начать с файлов
  - случайные предположения превращаются в правила навыка
  - исправлять приходится уже созданную структуру
- Сначала проектируется поведение
- Затем создаются файлы

## Что делает `skill-designer`

- Помогает понять, нужен ли для этой работы отдельный навык
- Проектирует навык до реализации
  - назначение
  - границы
  - входные материалы
  - ожидаемый результат
  - самостоятельные действия Codex
  - остановки и обращения к человеку
- Разбирает
  - новый навык
  - изменение существующего навыка
  - навык, который запускается или работает неправильно
- Не создаёт и не изменяет файлы проектируемого навыка
- Результат работы
  - согласованный проект навыка
  - основа для последующей реализации

## Пример с обновлением материалов курса

- Повторяющаяся работа
  - проверять официальный источник
  - получать новые материалы
- Общего описания недостаточно
  - какие файлы можно добавлять
  - что делать с изменёнными материалами участника
  - можно ли обновлять `README.md`
  - как действовать, если источник недоступен
- При проектировании определяются границы
  - новые официальные материалы добавляются
  - изменённые участником уроки не перезаписываются
  - конфликт показывается пользователю
  - недоступность источника не разрешает менять проект
- Только после этих решений можно правильно создать навык

## Из чего складывается проект навыка

- Повторяющаяся работа
  - не разовая задача
  - не ещё не проверенная случайная идея
- Ситуации запуска
  - подходящие запросы
  - похожие запросы, для которых навык не нужен
- Рабочий результат
  - что должно появиться или измениться
  - как понять, что работа закончена
- Границы самостоятельности
  - что Codex может решить и выполнить
  - где требуется решение или разрешение человека
- Необходимые ресурсы
  - подробные справочники
  - повторяющиеся программы
  - шаблоны готового результата
- Проверка
  - правильно ли навык выбирается
  - правильно ли выполняет свою работу

## Как спроектировать свой навык

- Установить `skill-designer`
  - через `$skill-installer`
  - из `https://github.com/dezvin/codex-skills`
- Открыть проект, где уже выполнялась нужная работа
- Передать Codex
  - описание повторяющейся работы
  - существующие материалы и правила
  - примеры удачного и неудачного результата
  - подтверждённые решения и ограничения
- Запустить
  - `$skill-designer`
- Обсудить только решения, которые действительно меняют будущий навык
- Получить проект навыка
- Проверить, соответствует ли он реальной работе
- Утвердить проект до создания файлов

## Проект навыка и готовый навык

- Результат `skill-designer`
  - ещё не установленный и не работающий навык
  - описание того, каким он должен быть
- После утверждения проекта
  - `$skill-creator` создаёт или изменяет файлы
  - проверяет техническую структуру навыка
- Разделение ролей
  - `skill-designer` отвечает за замысел и поведение
  - `skill-creator` отвечает за физическое создание и техническую проверку
- Созданный навык ещё нужно проверить
  - запускается ли он на подходящих задачах
  - не запускается ли на посторонних
  - соблюдает ли утверждённые границы
  - возвращает ли ожидаемый результат
