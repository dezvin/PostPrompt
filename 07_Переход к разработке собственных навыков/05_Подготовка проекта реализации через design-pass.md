# Микроурок 21. Подготовка проекта реализации через `design-pass`

## Обсуждение ещё не является проектом реализации

- Во время работы человек и Codex
  - рассматривают разные варианты
  - принимают решения
  - отказываются от прежних идей
  - откладывают отдельные вопросы
  - уточняют границы результата
- В длинном диалоге всё это перемешивается
- Последнее сообщение не содержит всей актуальной картины
- Если сразу перейти к реализации
  - отклонённая идея может вернуться как требование
  - предложение Codex может быть принято за решение пользователя
  - открытый вопрос может быть незаметно решён исполнителем
- Перед реализацией нужно восстановить, что действительно решено

## Что делает `design-pass`

- Разбирает материалы обсуждения
  - текущий диалог
  - переданный текст
  - документ
  - расшифровку
  - ранее подготовленный разбор решений
- Отделяет
  - подтверждённые решения
  - отклонённые варианты
  - решения, которые были заменены более поздними
  - противоречия
  - вопросы, которые ещё требуют ответа пользователя
- Не считает предложение Codex принятым решением
  - пока пользователь его не подтвердил
- Не придумывает ответы на содержательные вопросы за пользователя
- Не начинает реализацию

## Два результата `design-pass`

- Разбор решений
  - что принято
  - что отклонено
  - что изменилось
  - что осталось открытым
  - достаточно ли оснований для проектирования
- Полный проект реализации
  - требования
  - границы и исключения
  - устройство будущего решения
  - затрагиваемые части проекта
  - способы проверки
  - передача следующему исполнителю
- Нужный результат зависит от запроса
  - понять состояние решений
  - подготовить реализацию

## Пример с метасистемой проектов

- В обсуждении появились разные идеи
  - собирать задачи из нескольких проектов
  - показывать утреннюю сводку
  - выводить полный обзор
  - напоминать о задачах
  - выполнять задачи других проектов
- Позднее были приняты границы
  - утренняя сводка остаётся короткой
  - полный обзор открывается по запросу
  - жёсткие напоминания остаются во внешнем приложении
  - задачи выполняются внутри своих проектов
- `design-pass`
  - восстанавливает подтверждённые решения
  - не возвращает отвергнутые варианты
  - показывает оставшиеся противоречия
  - собирает согласованное устройство системы
  - готовит понятную передачу для реализации
- Исполнитель получает не историю разговора
  - а актуальный проект будущей системы

## Как провести `design-pass`

- Установить `design-pass`
  - через `$skill-installer`
  - из `https://github.com/dezvin/codex-skills`
- Передать Codex
  - что нужно спроектировать
  - какой материал содержит обсуждение и решения
  - нужен только разбор решений или полный проект реализации
- Запустить
  - `$design-pass`
- Ответить на критические вопросы
  - только если без них пришлось бы придумывать намерение пользователя
- Получить проект реализации
- Проверить
  - все ли принятые решения сохранены
  - не вернулись ли отклонённые варианты
  - видны ли открытые вопросы
  - понятно ли, что и как должен сделать следующий исполнитель

## Проект реализации и сама реализация

- Результат `design-pass`
  - готовая основа для передачи работы
  - ещё не выполненная реализация
- Готовый проект не разрешает автоматически
  - изменять файлы
  - создавать систему
  - запускать публикацию
  - выполнять другие внешние действия
- После утверждения
  - пользователь отдельно поручает реализацию
  - исполнитель работает по согласованному проекту
  - результат проверяется по зафиксированным условиям
