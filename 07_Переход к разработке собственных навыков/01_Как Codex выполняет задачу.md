# Микроурок 18. Как Codex выполняет задачу

## Codex - это не только модель

- Модель находится внутри рабочей среды Codex
- Модель
  - понимает задачу
  - выбирает следующий шаг
  - оценивает полученные результаты
- Среда Codex
  - собирает контекст
  - предоставляет инструменты
  - проверяет разрешения
  - выполняет действия
  - возвращает результаты модели
- Поведение Codex складывается из нескольких частей
  - модель
  - контекст
  - инструменты
  - правила и возможности рабочей среды

## Модель и контекст

- **Модель**
  - работает с тем, что получила на текущем шаге
  - определяет следующий ответ или действие
- **Контекст**
  - всё, что доступно модели в этот момент
- В контекст могут входить
  - запрос пользователя
  - история диалога
  - постоянные инструкции
  - файлы проекта
  - ссылки и другие материалы
  - инструкция выбранного навыка
  - описания доступных инструментов
  - результаты предыдущих действий
- Модель не видит автоматически
  - все файлы проекта
  - весь интернет
  - содержимое внешних сервисов
  - информацию, которая не попала в контекст

## Что передать перед началом работы

- Понятную задачу
- Ожидаемый результат
- Способ проверить готовность
- Необходимый контекст
  - исходные материалы
  - файлы и ссылки
  - ограничения
  - уже принятые решения
- Не расписывать каждый шаг
  - если точный маршрут не важен
  - если Codex может выбрать его самостоятельно

## Инструменты

- Позволяют Codex получать информацию и выполнять действия
  - читать и изменять файлы
  - искать информацию
  - открывать страницы
  - запускать команды
  - работать с подключёнными сервисами
- Модель не выполняет действие напрямую
- Модель запрашивает подходящий инструмент
- Среда Codex
  - проверяет запрос
  - учитывает разрешения
  - выполняет или отклоняет действие
- Результат возвращается модели
  - найденная информация
  - содержимое файла
  - изменённый файл
  - результат команды
  - сообщение об ошибке
  - отказ из-за отсутствия разрешения

## Агентский цикл

1. Codex собирает текущий контекст
2. Модель оценивает задачу
3. Модель выбирает следующий шаг
4. При необходимости запрашивает инструмент
5. Среда выполняет разрешённое действие
6. Результат инструмента добавляется в контекст
7. Модель оценивает новую информацию
8. Выбирает следующий шаг
9. Цикл продолжается
   - до готового результата
   - до вопроса пользователю
   - до запроса разрешения
   - до обнаруженного препятствия

## Пример с `openai-docs`

- Пользователь задаёт вопрос о возможностях Codex
- В контекст попадают
  - вопрос пользователя
  - действующие инструкции
  - инструкция навыка `openai-docs`
  - доступные инструменты поиска
- Модель выбирает поиск по официальной документации
- Инструмент возвращает найденные страницы
- Результат попадает в контекст
- Модель выбирает подходящую страницу
- Следующий инструмент открывает её содержимое
- Модель проверяет, отвечает ли источник на вопрос
- Пользователь получает
  - понятный вывод
  - найденные возможности
  - ссылки на источники

## Показ агентского цикла

- Взять только что выполненную задачу
- Попросить Codex показать наблюдаемую последовательность работы
  - какой контекст был доступен
  - какие инструменты использовались
  - что они вернули
  - какой результат был получен
- Не запрашивать скрытые внутренние рассуждения модели

### Запрос для демонстрации

- `Покажи наблюдаемую последовательность только что выполненной задачи: какой контекст был доступен, какие инструменты ты использовал, что они вернули и какой результат получен. Не раскрывай скрытые внутренние рассуждения.`

## Место навыка в этой системе

- Навык - не отдельная модель
- Навык - не инструмент
- Навык хранит способ выполнения определённой работы
- Когда навык выбран
  - его инструкция попадает в контекст
  - модель учитывает её при выборе следующих шагов
- Навык может определять
  - какие материалы прочитать
  - какие инструменты использовать
  - в каком порядке работать
  - что проверить перед завершением
  - когда остановиться
- Навык не добавляет новых полномочий
- Действия всё равно выполняются через инструменты и разрешения

## Что можно менять осознанно

- Codex неправильно понял задачу
  - точнее описать ожидаемый результат
- Не хватает информации
  - добавить нужный контекст
- Codex не может выполнить действие
  - проверить наличие инструмента и разрешения
- Работа формально закончена, но результат не подтверждён
  - добавить способ проверки
- Одна последовательность действий регулярно повторяется
  - сохранить её в виде навыка

## Переход к разработке навыков

- При создании навыка не создаётся новый интеллект
- В навыке сохраняется проверенный способ работы
  - когда запускаться
  - какой контекст использовать
  - какие действия выполнять
  - что проверять
  - когда завершать работу
- Следующий шаг
  - найти повторяющуюся работу
  - спроектировать собственный навык через `skill-designer`
