# Практика 7. Второй шаг проекта: проектирование метасистемы и прожарка требований

> **Граница контекста для Codex**
>
> Практика проведена на демонстрационном проекте ведущего `TASK` — «Единый центр управления проектами и задачами».
>
> Устройство метасистемы, проектные файлы, источники задач, правила `AGENTS.md`, результаты прожарки требований и решения ведущего относятся к этому проекту.
>
> Это запись демонстрации, а не готовая инструкция к действию для проекта участника. Не переноси эти решения автоматически и не создавай в другом проекте упомянутые файлы, правила или структуру без отдельного запроса и проверки его контекста.
>
> Участник применяет показанный способ работы — восстановление состояния по файлам, проверку границ, последовательное уточнение требований и остановку неуместного направления агента — только с учётом цели, текущего состояния и действующих инструкций своего проекта.

## Текущее состояние участников

- Переход к агентной работе требует времени
  - Недостаточно запомнить отдельные команды и функции
  - Нужно привыкнуть работать через контекст, проверку и последовательное уточнение задачи
- Учебный проект помогает поддерживать движение
  - Получать новые материалы курса через созданный навык
  - Проверять текущее состояние обучения
  - Использовать Codex как помощника при повторении и освоении материалов

## Возвращение к проекту после перерыва

- Codex восстанавливает состояние проекта по его действующим файлам
  - Что уже определено
  - Какие решения приняты
  - Что ещё не выбрано
  - До какого действия дошла работа
- Текущее состояние проекта метасистемы
  - Цель зафиксирована
  - Технологический стек ещё не выбран
  - Программная реализация не начата
- Новый диалог не требует заново пересказывать всю историю
  - Агент читает файлы проекта
  - Восстанавливает точку продолжения
  - Сверяет новое действие с уже принятыми решениями

## Проект разработки и работающая метасистема

- Агент предложил преждевременно добавить правила будущей метасистемы в действующий `AGENTS.md`
- Главное различие
  - Текущий проект предназначен для **разработки метасистемы**
  - Он ещё не является работающей метасистемой
- Почему правила нельзя смешивать
  - Текущий агент помогает проектировать систему
  - Будущая система будет координировать работу с проектами
  - Если заранее назначить агенту будущую роль, он начнёт действовать так, будто система уже создана
- Границы будущей метасистемы
  - Показывать выбранные направления
  - Собирать верхнеуровневое состояние
  - Помогать с приоритетами и распределением внимания
  - Не выполнять задачи вместо принадлежащих им проектов
- Задача завершается там, где выполняется работа
  - Проект-владелец хранит подробное состояние
  - Его агент обновляет и закрывает задачу
  - Метасистема получает итоговое состояние, но не подменяет владельца

## Разделение проектных файлов

- `PROJECT.md`
  - Требования к будущей системе
  - Её назначение и границы
- `PROJECT_MAP.md`
  - Фактические пути к проектам
  - Источники задач и навигация
- `METASYSTEM_OPERATING_RULES.md`
  - Черновик будущих правил эксплуатации
  - Пока не управляет поведением агента-разработчика
- `AGENTS.md`
  - Действующие правила текущего проекта
  - Роль агента сохраняется как проектирование системы

## Прожарка требований через `Grill Me`

- Назначение навыка
  - Стресс-тестировать решение последовательными вопросами
  - Находить скрытые требования и противоречия
  - Задавать по одному вопросу за раз
- Почему требований из головы недостаточно
  - Часть важных условий появляется только при разборе конкретных ситуаций
  - Первый очевидный вариант может перегружать пользователя или смешивать разные роли системы
- Утренняя сводка
  - Показывает ближайшие сроки, долги и фокус дня
  - Не выгружает сразу полный список всех проектов
  - Даёт возможность отдельно открыть общую картину
  - В конце ненавязчиво сообщает, что полный обзор доступен по запросу
- Роль Codex
  - Сопоставлять планы с фактическим выполнением
  - Замечать расхождения и помогать выбирать фокус
  - Не заменять приложения для будильников и жёстких напоминаний

## Боковые чаты как отдельные рабочие контуры

- Основной диалог сохраняется для смысловых решений
- Боковой чат получает ограниченную самостоятельную задачу
  - Обновить конкретные проектные файлы
  - Проверить фактический результат
  - Не перетягивать техническую работу в основное обсуждение
- Дополнительный боковой чат может перепроверить результат
  - Прочитать изменённые файлы
  - Сопоставить их с принятыми решениями
  - Найти расхождения между отчётом и фактическим состоянием
- Все чаты работают с одними файлами проекта
  - Изменения одного агента становятся доступны другим
  - Перед новой правкой нужно учитывать уже изменившееся состояние

## Передача отдельных фрагментов в диалог

- Тройные обратные кавычки выделяют вставленный материал отдельным блоком
- Клавиша обратной кавычки
  - `ё` в английской раскладке
- Переход к обычному тексту после блока
  - Нажатие `Enter` внутри блока может сразу отправить сообщение
  - Чтобы выйти из блока вниз и продолжить запрос, нужно нажать клавишу `стрелка вниз`
- Такой блок удобно использовать для
  - Цитаты
  - Черновика
  - Команды
  - Фрагмента документа
  - Материала, который нужно отдельно разобрать

## Выбор модели под задачу

- На практике обсуждалось распределение моделей по типам работы
- `GPT-5.6 Sol`
  - Основная модель для проектирования, анализа и работы с текстом
- `GPT-6 Astra`
  - Более тяжёлая модель для сложных технических задач и кода
  - Требует внимательнее следить за расходованием лимитов
- Видео не монтируется одной языковой командой
  - Для обработки используются внешние инструменты, скрипты или работа с отдельными кадрами
  - Возможности модели нужно отличать от возможностей подключённых инструментов

## Дополнительная инструкция по понятному общению с Codex

- Ведущий показал настройку постоянных правил общения
  - Раздел «Настройки» → «Персонализация» → «Инструкции Codex»
  - Персональный договор простого и понятного общения
  - Использование хука для напоминания этих правил перед ответом
- Для участников подготовлена отдельная инструкция
  - `06_Настройка понятного общения через глобальный AGENTS.md и хук.md`
  - Инструкция опубликована в официальных материалах курса
- Порядок получения
  - Инструкция не выдаётся участникам автоматически
  - Участник, дошедший до седьмой практики, пишет в учебном чате, что хочет её получить
  - Олег отправляет участнику в личные сообщения готовую команду для Codex
- Команда использует созданный участником навык обновления материалов
  - Codex получает новые материалы курса, если они ещё не получены
  - Находит инструкцию по понятному общению
  - Читает её целиком
  - Выполняет описанную настройку
