## Установка навыков

### Предыстория с областью установки

- Ранее участница обнаружила ошибку в первоначальной инструкции
- Навыки устанавливались глобально вместо установки в конкретный проект
- До практики ведущий исправил инструкцию в Google Документе
- На практике использовалась уже исправленная формулировка
- Целевая папка проекта
  - `.agents/skills/`

### Использование `$skill-installer`

- Системный навык устанавливает готовые сторонние навыки
- Для демонстрации требовалась локальная установка в проект
- В установочном запросе была явно указана проектная папка
- Устанавливаемая связка
  - `manage-project-tasks`
  - `nearest-clarity`
  - `zoom-out`
  - `zero-trust`

### Ошибка с дублированием навыков

- По первой команде агент скопировал в проект все четыре навыка
- Глобальную область перед установкой он не проверил
- Ведущий обнаружил это по отчёту агента
- Ведущий поручил
  - проверить глобально установленные навыки
  - найти локальные дубли
  - удалить ненужные проектные копии
- Глобально уже были доступны
  - `zoom-out`
  - `zero-trust`
- Их локальные копии удалили из `.agents/skills/`
- В проекте остались
  - `manage-project-tasks`
  - `nearest-clarity`

### Практический вывод

- Явно указанная область установки не заменяет проверку результата
- Агент может выполнить формальную команду и не учесть существующее окружение
- После установки нужно проверить
  - какие навыки появились в проекте
  - какие навыки уже доступны глобально
  - возникли ли дубли
  - соответствует ли итоговая структура поставленной задаче

## Прямой вызов навыков

- Доступный навык можно вызвать через символ `$`
- В английской раскладке
  - `Shift + 4`
- После ввода `$` появляется список доступных навыков
- Прямой вызов позволяет
  - гарантированно передать задачу конкретному навыку
  - не ждать автоматического срабатывания триггера
  - попросить агента объяснить назначение и условия применения навыка
- На практике напрямую вызывались
  - `$manage-project-tasks`
  - `$nearest-clarity`
  - `$zoom-out`
- Навык также может сработать автоматически, если запрос соответствует его триггерам

## Настройка работы с задачами

### Роль `manage-project-tasks`

- Навык ведёт долговременное состояние работы
- Открытые задачи хранятся в `TODO.md`
- Закрытые задачи переносятся в `archive/tasks/YYYY-MM.md`
- Подробный жизненный цикл задачи принадлежит самому навыку
- В `AGENTS.md` остаются правила его использования в конкретном проекте

### Какие задачи нужно сохранять

- Незавершённая работа, которая должна продолжиться в другом диалоге
- Конкретная блокировка
- Осознанно отложенное действие
- Самостоятельная будущая работа, которую нельзя потерять

### Что не становится отдельной задачей

- Чтение файла
- Разовая правка
- Обсуждение варианта
- Промежуточный технический шаг
- Несколько действий, которые полностью выполняются в текущем диалоге

### Правила демонстрационного проекта

- Агент предлагает сохранить задачу только при наличии долговременной работы
- Создание новой задачи согласуется с пользователем
- Молчание не считается согласием
- После подтверждения фактического результата задача закрывается без лишнего повторного вопроса
- Агент не отменяет незавершённую задачу самостоятельно
- Статус определяется по фактическому результату и доступным доказательствам
- Значимая завершённая работа, которой не было в плане
  - не проводится задним числом через временную задачу в `TODO.md`
  - фиксируется непосредственно в `archive/tasks/YYYY-MM.md`
- Эти правила были приняты для проекта `TASK`
- В другом проекте правила могут отличаться и должны проверяться отдельно

### Различие пользовательских запросов

- «Какие задачи?» или «Что нужно сделать?»
  - прочитать `TODO.md`
  - показать уже зафиксированную открытую работу
- «Что дальше?» или «Куда двигаться?»
  - прочитать действующее описание проекта
  - определить ближайший полезный участок через `nearest-clarity`
- Предложенное направление не становится задачей автоматически
  - сначала принимается решение
  - затем при необходимости вызывается `manage-project-tasks`

## Проверка и уточнение проектных правил

### Боковые чаты

- Временные изолированные ветки внутри текущей работы
- В показанной версии интерфейса
  - исчезают после закрытия приложения
  - можно открыть несколько боковых чатов
- На практике использовались
  - «Боковой чат 1»
  - «Боковой чат 2»
- В боковой чат можно передать отдельный фрагмент контекста
  - непонятную команду
  - скрипт PowerShell
  - проектное правило
  - проверяемую гипотезу
- Пример запроса
  - `Объясни на простом языке`
- Боковой чат помогает не перегружать основной диалог
- Его результат не переносится в проект автоматически
- Значимый вывод проверяется и осознанно возвращается в основную работу

### `token-efficient`

- Использовался для уплотнения правил `AGENTS.md`
- Из текста убирались
  - повторы
  - многословные пояснения
  - одинаковые правила для одинаковых ситуаций
- При сжатии сохранялись
  - границы разрешений
  - условия вызова навыков
  - различия между типами задач
  - ответственность человека и агента

### `zero-trust`

- Черновик правил рассматривался как материал, который может содержать ошибки
- Проверялись
  - формулировки правил
  - фактическая структура проекта
  - реально созданные файлы
  - полномочия агента
  - соответствие результата исходной задаче
- После проверки уточнили
  - агент не отменяет задачи без решения человека
  - при обнаружении другой системы задач агент останавливается
  - перед изменением сохраняется исходная точка, с которой сравнивается результат
- Уверенный отчёт агента не заменяет проверку фактического состояния

### Подготовка переносимого промпта

- Согласованные правила упаковали в отдельный промпт
- Назначение
  - быстро настраивать работу с задачами в других проектах
  - не воспроизводить весь процесс согласования вручную
- Переносимый промпт проверили в боковом чате через `zero-trust`
- Проверка выявила дополнительные ограничения
  - запрет самовольной отмены задач
  - остановка при обнаружении другой системы задач
  - сохранение исходной точки проекта перед изменениями
- Итоговый промпт оформлен отдельным файлом
  - `Настройка Agents для задач.txt`
- Файл добавлен в официальные материалы блока
  - `06_Установка и использование навыков/Настройка Agents для задач.txt`
- Участник может передать файл Codex или целиком скопировать его содержимое
- Каноническая версия хранится вместе с учебными материалами
- После публикации обновления участники получат файл через Git
- При использовании в другом проекте правила нужно сопоставить с его устройством и действующими инструкциями

## Демонстрация `nearest-clarity`

### Исходная неопределённость

- Основа проекта подготовлена
- Полная реализация ещё не спроектирована
- Существует несколько возможных направлений
- Попытка заранее определить весь маршрут потребовала бы неподтверждённых предположений

### Работа навыка

- Прочитать действующее описание в `PROJECT.md`
- Определить фактическую стадию проекта
- Выделить ближайший законченный участок работы
- Назвать результат, который завершит этот участок
- Оставить последующие этапы предварительными

### Предложенный ближайший участок

- Собрать реальные источники существующих проектов и задач
- Понять, откуда система должна получать актуальное состояние
- Использовать фактические данные как основание следующего решения

### Результат

- Появился конкретный участок, с которого можно начать
- Дальний маршрут остался предварительным
- Первое действие было передано в контур управления задачами

- Первая долговременная задача получила статус `pending`

- Новый файл зарегистрирован в `PROJECT_MAP.md`
- Появилась точка продолжения работы для следующего диалога

## Демонстрация `zoom-out`

### Задача навыка

- Проверить, не застряла ли работа в слишком узкой рамке
- Сопоставить текущий шаг с общей целью проекта
- Найти неверное предположение или потерянное ограничение

### Неудачное направление

- Навык посчитал выбранный шаг слишком техническим
- Предложил вернуться к общему пересмотру требований
- Базовые рамки при этом уже были утверждены в `PROJECT.md`

### Вмешательство человека

- Ведущий остановил повторное обсуждение утверждённых решений
- Указал агенту использовать действующий `PROJECT.md`
- Вернул работу к принятому практическому шагу
- Не позволил навыку заменить утверждённую основу новой постановкой задачи

### Практический вывод

- Вызов навыка не гарантирует полезный ответ
- `zoom-out` помогает проверить направление, но не отменяет действующие решения
- Человек оценивает уместность предложения
- При неверном направлении нужно указать на действующего владельца истины и вернуть агента к задаче

## Как навыки работают вместе

- `$skill-installer`
  - устанавливает готовые навыки
- `nearest-clarity`
  - определяет ближайший полезный участок при реальной неопределённости
- `manage-project-tasks`
  - сохраняет принятую долговременную работу между диалогами
- `zoom-out`
  - проверяет, не потеряна ли общая цель и не стала ли рамка слишком узкой
- `zero-trust`
  - проверяет основания, полномочия и фактический результат
- `token-efficient`
  - уплотняет инструкции без потери действующих правил
- Человек
  - определяет стратегию
  - принимает содержательные решения
  - задаёт границы
  - останавливает лишние циклы
  - подтверждает результат

## Самостоятельная работа участников

- Установить необходимую связку навыков в собственный рабочий проект
- Проверить
  - какие навыки уже доступны глобально
  - какие навыки нужны локально
  - не появились ли дубли
- Настроить правила управления задачами для своего проекта
- Не копировать автоматически правила проекта `TASK`
- При необходимости использовать `Настройка Agents для задач.txt` как основу настройки
- Проверить предложенные правила перед записью в `AGENTS.md`
- Использовать `nearest-clarity`, когда дальнейший маршрут действительно зависит от ещё неизвестных данных
- Сохранять принятую долговременную работу через `manage-project-tasks`
- Применять `zoom-out`, когда работа зациклилась или потеряла связь с общей целью
- Проверять основания и фактический результат через `zero-trust`
- При неверном направлении останавливать агента и возвращать его к утверждённым файлам проекта
