# Микроурок 11. Создание собственного рабочего проекта

## Что уже готово

- Проект уже выбран
  - зачем он нужен;
  - какой результат должен дать;
  - что входит в первую полезную версию;
  - какие есть границы и неизвестные.
- Карточка пока находится в учебном проекте
- Это исходное описание будущей работы
- Следующий переход
  - не выбирать проект заново;
  - не начинать реализацию;
  - создать для него отдельную рабочую среду.

## Что войдёт в новый проект

- **Проект**
  - отдельное рабочее направление в Codex
- **Папка**
  - реальные материалы и результаты на компьютере
- **Диалоги**
  - отдельные задачи и этапы внутри общей работы
- **`PROJECT.md`**
  - действующее описание проекта
- **`AGENTS.md`**
  - постоянные правила работы Codex
- **`PROJECT_MAP.md`**
  - устройство проекта и навигация по файлам
- **Исходные материалы**
  - содержание, с которым предстоит работать
- Элементы уже знакомы по учебному проекту
- Новое действие
  - применить их самостоятельно к выбранному проекту.

## Порядок действий

1. Найти `Карточка выбранного проекта.md` в учебном проекте
2. Открыть расположение файла в Проводнике
3. Создать отдельную папку для собственного проекта
4. Открыть папку как новый проект в Codex
5. Скопировать карточку в корень нового проекта
6. Передать карточку Codex как исходное описание проекта
7. Последовательно создать основные служебные файлы
8. Добавить доступные исходные материалы
9. Проверить рабочую среду в новом диалоге

- Новый инструмент для этого перехода не нужен
- Участник повторяет уже изученный способ работы
- Codex помогает подготовить файлы
- Решения, содержание и проверка остаются за человеком

## Что хранит каждый файл

### `Карточка выбранного проекта.md`

- Сохраняет первоначальный выбор участника
- Остаётся в корне как исходный документ
- Не заменяется новым пересказом по памяти

### `PROJECT.md`

- Переводит карточку в действующее описание проекта
- Фиксирует
  - цель;
  - полезный результат;
  - первую рабочую версию;
  - границы;
  - исходные материалы;
  - зависимости и неизвестные;
  - признаки готовности.

### `AGENTS.md`

- Задаёт правила работы Codex именно в этом проекте
- Объясняет
  - где находится действующее описание;
  - каким источникам доверять;
  - когда читать карту проекта;
  - какие изменения требуют подтверждения;
  - что нельзя придумывать или делать самостоятельно.

### `PROJECT_MAP.md`

- Показывает фактическое устройство проекта
- Объясняет назначение основных файлов и папок
- Помогает находить нужный материал без просмотра всего проекта
- Обновляется вместе с реальной структурой

### Исходные материалы

- Документы, данные, ссылки, изображения и другие материалы для первой версии
- Только то, что уже есть или действительно понадобится в ближайшей работе
- Структура создаётся под реальные материалы, а не заранее ради красивых папок

## Первый запрос к Codex

```text
Изучи файл «Карточка выбранного проекта.md».

Это утверждённое исходное описание моего проекта.

Помоги мне на его основе настроить рабочий проект: подготовить PROJECT.md,
проектный AGENTS.md, PROJECT_MAP.md и определить место исходных материалов.

Не начинай реализацию проекта и не создавай файлы задач или состояния.

Работай по одному файлу: сначала показывай черновик, после моего подтверждения
сохраняй его и проверяй записанный результат.
```

## Проверка в новом диалоге

- Изменения в `AGENTS.md` надёжнее проверять в новом диалоге
- Новый диалог не получает всю историю настройки
- Он должен понять проект по сохранённым файлам

```text
Изучи текущий проект и кратко объясни:

- его цель;
- первую рабочую версию;
- установленные границы;
- основные материалы;
- существенные неизвестные.

Ничего не редактируй и не начинай реализацию.
```

- Codex правильно восстановил проект
  - рабочая среда собрана;
  - следующий диалог может продолжать работу.
- Codex потерял цель, перепутал границы или не нашёл материалы
  - исправить служебные файлы или навигацию;
  - не компенсировать проблему новым длинным пересказом в каждом диалоге.

## На чём остановиться

- Собственный проект создан и первоначально настроен
- Карточка сохранена как исходный документ
- Основные служебные файлы связаны между собой
- Исходные материалы получили понятное место
- Проект проверен в новом диалоге
- `TODO.md` и другие файлы состояния пока не создаются
- Навыки и управление задачами начинаются в следующем блоке
- Реализация первой полезной версии начинается после первоначальной настройки
