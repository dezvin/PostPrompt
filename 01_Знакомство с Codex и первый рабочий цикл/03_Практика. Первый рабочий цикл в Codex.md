# Первая практика: первый рабочий цикл в Codex

## Как устроена мастерская

- Микроуроки
  - необходимая теория
  - отдельные элементы работы в Codex
  - материалы, к которым можно возвращаться
- Практические встречи
  - соединение отдельных элементов в общую работу
  - демонстрация на реальном проекте
  - сквозной проект преподавателя
    - выбор темы через голосование участников
    - продолжение проекта на следующих практиках
  - вопросы и разбор затруднений
  - перенос подхода в проекты участников
- Роль участника
  - первый пилот
  - удерживает управление, ответственность и общую картину
  - приносить собственный профессиональный контекст
  - принимать решения
  - проверять результат
  - постепенно собирать свой проект
- Роль Codex
  - второй пилот
  - предлагает маршрут и варианты действий
  - разбираться в материалах
  - выполнять конкретную работу
  - создавать и изменять результаты
  - помогать с проверкой и исправлением

## «ПостПромпт» как живой проект в Codex

- Мастерская создаётся в той же среде, которую изучают участники
- Внутри проекта связаны
  - устройство продукта
  - программа
  - уроки
  - публикации
  - задачи
  - принятые решения
- Папка проекта
  - реальные рабочие файлы
  - исходные материалы
  - утверждённые результаты
- Отдельные диалоги
  - подготовка урока
  - работа над публикацией
  - проверка материалов
  - продолжение следующего этапа
- Один проект
  - много разных результатов
  - общие материалы
  - продолжающаяся работа между диалогами

## Как движется работа в Codex

- Разделение рабочих сред
  - свободное обсуждение и поиск идеи — в ChatGPT
  - целевая работа с файлами проекта — в Codex
- Экономия лимита
  - Luna для знакомства с интерфейсом и простых экспериментов
- Человек определяет
  - что сейчас нужно получить
  - где находятся материалы
  - что важно сохранить
  - как будет проверяться результат
- Codex
  - изучает материалы проекта
  - восстанавливает нужный контекст
  - предлагает или выполняет следующий шаг
  - показывает свои действия
- Человек
  - проверяет направление
  - периодически отдаляется от локальной задачи и проверяет общую картину
  - контролирует действия
  - открывает реальный результат
  - уточняет или исправляет работу
- Если информации стало слишком много
  - остановить работу
  - сделать паузу
  - запросить сводку по сделанному и созданным файлам
- Результат
  - остаётся в файлах проекта
  - может использоваться в следующих диалогах
  - не зависит только от истории одного разговора

## Один цикл на живом примере

- Открыть проект «ПостПромпт»
- Минимальный учебный пример
  - чистый проект «Обучение ПостПромпт 2»
  - создание файла `Привет.txt`
  - изменение файла в диалоге
  - открытие результата на компьютере
  - продолжение работы с файлом в новом диалоге
- Показать существующие материалы
  - два подготовленных микроурока
  - разные файлы
  - связь между ними
- Создать отдельный диалог для новой задачи
- Поставить одну небольшую понятную задачу
- Сначала попросить Codex разобраться в материалах
- Увидеть предложенное направление
- Продолжить работу после проверки
- Посмотреть действия Codex
- Остановиться на запросе подтверждения
  - понять, какое действие предлагается
  - проверить, соответствует ли оно задаче
- Открыть фактический результат
- Сравнить его с поставленной задачей
- Запросить одну конкретную правку

## Что участники должны увидеть в демонстрации

- Интерфейс связан с реальной работой
- Проект больше одного диалога
- Папка хранит общие материалы и результаты
- Новый диалог решает отдельную задачу
- Codex не должен начинать с бесконтрольного выполнения
- Действия можно видеть, уточнять и останавливать
- Сообщение о готовности не заменяет проверку файла
- Ошибку можно исправить конкретной правкой без перезапуска всей работы
