# Микроурок 22. Субагенты: отдельный помощник для части работы

## Общая задача и отдельный помощник

- Основной агент ведёт общую работу
  - удерживает цель и принятые решения
  - выделяет отдельное поручение
  - принимает результат и продолжает работу
- **Субагент**
  - отдельный помощник для ограниченной части задачи
  - работает в своей ветке со своим контекстом
  - возвращает результат основному агенту
- Отдельная работа может быть
  - исследованием одного вопроса
  - разбором части большого материала
  - извлечением сведений по заданным правилам
  - проверкой готового результата
- Отличие от навыка
  - навык хранит способ работы
  - субагент выполняет отдельное поручение
  - навык может предусматривать запуск субагентов

## Зачем выносить часть работы

- Сохранить внимание основного агента на общей задаче
  - промежуточные поиски, чтение и длинные отчёты остаются у помощника
  - в основной диалог возвращается нужный результат
- Выполнять независимые направления параллельно
  - разные помощники разбирают разные вопросы
  - основной агент сопоставляет и объединяет результаты
- Посмотреть на готовый материал отдельно от процесса его создания
  - проверяющему передаются результат и основания для проверки
  - ему не требуется вся авторская переписка

### Почему отдельный проверяющий может быть полезен

- Агент, создавший результат, уже видит свою предыдущую версию и её обоснования
- При проверке он может отдавать предпочтение собственному ответу
  - искать подтверждения
  - сохранять прежние предположения
  - недостаточно замечать противоречащие сведения
- У языковых моделей встречается поведение, похожее на человеческие когнитивные искажения
  - **предвзятость подтверждения** — искать подтверждение своей версии вместо попытки её опровергнуть
  - **предпочтение собственного ответа** — оценивать свою работу благосклоннее
- Такое поведение наблюдалось в исследованиях моделей
  - [предвзятость подтверждения](https://arxiv.org/abs/2604.02485)
  - [предпочтение собственных ответов при самопроверке](https://arxiv.org/abs/2402.11436)
- Отдельное задание проверяющему
  - искать расхождения с источниками и требованиями
  - не защищать решения автора
- Самопроверка тоже может быть полезной
  - отдельный помощник добавляет другой способ проверки
  - но не гарантирует отсутствие ошибок

## Что передать помощнику

- Одну понятную задачу
  - какую часть работы нужно выполнить
- Необходимые материалы
  - исходники
  - нужные файлы и ссылки
  - согласованные требования и решения
- Границы действий
  - что можно делать
  - что делать нельзя
- Ожидаемый результат
  - что именно вернуть
  - по каким признакам поручение выполнено
- Собственный контекст не означает автоматически пустую историю
  - состав передаваемых материалов нужно задать
  - для отдельной проверки попросить не передавать историю создания результата
  - существенные решения из этой истории передать как согласованные требования

## Модель и сила мышления

- Помощник может использовать
  - ту же модель, что основной агент
  - другую доступную модель
- Модель выбирается под характер поручения
  - более сильная — для сложного анализа и неоднозначных решений
  - более экономичная — для рутинной работы по понятным правилам
- **Усилие мышления**
  - сколько ресурса модель выделяет на обдумывание задачи
  - задаётся отдельно от выбора модели
  - более высокое значение обычно увеличивает время и расход
- Модель и усилие можно указать прямо в запросе
- Пример сочетания
  - `GPT-6 Luna`
  - усилие мышления `xhigh`
  - Luna поддерживает этот уровень
  - `xhigh` — высокое усилие, а не режим минимального расхода
- Пример рутинного поручения
  - `Запусти субагента на GPT-6 Luna с усилием мышления xhigh. Пусть извлечёт из указанных материалов все ссылки и названия файлов, сохранив точные формулировки. Вернуть сгруппированный список. Файлы не менять.`
- Если настройки не указаны отдельно
  - помощник по умолчанию наследует модель и усилие основного агента
- Основание настроек
  - [выбор модели и усилия для субагента](https://learn.chatgpt.com/docs/agent-configuration/subagents#choosing-models-and-reasoning)
  - [поддерживаемые уровни GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)

## Сначала поручение, затем запуск

- Не обязательно самостоятельно писать точное задание помощнику
- Можно своими словами наговорить
  - чего хочется от всей работы
  - что должен сделать основной агент
  - какую часть поручить субагенту
- Попросить Codex сначала оформить задание
  - цель
  - материалы
  - ограничения
  - модель и усилие мышления
  - возвращаемый результат
- Запрос
  - `По моему описанию составь точное задание для субагента и сначала покажи его мне. Отдельно укажи, что сделаешь ты и что сделает помощник. До моего явного одобрения субагента не запускай.`
- Проверить предложенное поручение
  - правильно ли выделена отдельная часть работы
  - передаются ли нужные сведения
  - нет ли лишних действий
- Исправить или одобрить
- Только после одобрения запускать помощника

## Пример: проверка готового конспекта

- Основной агент подготовил конспект по исходному материалу
- Проверяющему передаются
  - исходный материал
  - готовый конспект
  - требования к конспекту
  - утверждённые изменения относительно исходника
  - критерии готовности
- Авторская переписка целиком не передаётся
- Поручение проверяющему
  - найти расхождения с исходником
  - найти добавления без достаточного основания
  - найти невыполненные требования
  - показать конкретные места и основания замечаний
- Пример расхождения
  - в исходнике вопрос оставлен открытым
  - в конспекте решение описано как принятое
  - проверяющий показывает оба фрагмента
- Граница проверки
  - не переписывать конспект
  - не изменять файлы
  - вернуть замечания для разбора

### Что делать с замечаниями

- Человек проверяет основания каждой находки
  - действительное расхождение
  - невыполненное требование
  - вкусовое предпочтение
  - недостаток сведений у проверяющего
- Решение остаётся за человеком
  - принять замечание
  - отклонить с понятной причиной
  - уточнить недостающие данные
- Совпадение ответов двух агентов
  - само по себе не подтверждает правильность

## Как наблюдать и управлять работой в Codex

- Для разового поручения достаточно прямого запроса
  - заранее создавать постоянный профиль помощника не обязательно
- После запуска
  - в основном диалоге появляется активность субагента
  - можно открыть его отдельную ветку
  - посмотреть ход работы и результат
- Через основной диалог можно попросить
  - уточнить задание работающему помощнику
  - остановить его
  - закрыть завершённую ветку
- Если запущено несколько помощников
  - указать, нужно ли дождаться всех результатов
  - определить, как объединить их ответы
- Субагент наследует действующие ограничения доступа
  - отдельная ветка не означает отсутствие права менять файлы
  - границу «только проверять, файлы не менять» нужно задать явно
- Эти возможности описаны в [документации Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents#managing-subagents)

## Субагенты внутри навыка

- Повторяющийся порядок делегирования можно включить в навык
  - когда запускать помощника
  - какую работу ему поручать
  - какие материалы передавать
  - какую модель и усилие использовать
  - что получать обратно
  - как использовать результат
- Пример — [`adaptive-web-research`](https://github.com/dezvin/codex-skills/tree/main/skills/adaptive-web-research)
  - основной агент удерживает исследовательский вопрос
  - исследовательский помощник ищет и читает источники
  - аналитик сопоставляет полученные сведения
  - при обнаружении пробела исследователю возвращается уточнённое поручение
  - основной агент собирает итоговый ответ
- Пользователю не нужно каждый раз заново описывать весь порядок
  - он уже задан в навыке
- Не любой навык запускает субагентов
  - это зависит от его инструкций
  - нужные помощники и инструменты должны быть доступны в среде

## Польза и цена параллельной работы

- В исследовательской системе Anthropic
  - ведущий агент разделяет сложный вопрос на направления
  - помощники исследуют их в собственных контекстах
  - возвращают существенные находки
  - ведущий объединяет результаты
- Такая схема особенно полезна
  - при большом объёме информации
  - при нескольких независимых направлениях
  - когда всю промежуточную работу неудобно держать в одном диалоге
- Параллельность может ускорять работу и расширять охват
- Но появляются дополнительные затраты
  - обращения к моделям и инструментам
  - постановка отдельных заданий
  - ожидание и сопоставление результатов
- Неясное разделение приводит к проблемам
  - помощники дублируют работу
  - пропускают вопросы
  - возвращают плохо совместимые результаты
- Если все шаги тесно зависят друг от друга
  - параллельная работа может быть неудобной
- Практический вывод
  - выделять помощника ради конкретной пользы
  - для короткой цельной задачи один агент часто проще
- [Разбор системы Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)
