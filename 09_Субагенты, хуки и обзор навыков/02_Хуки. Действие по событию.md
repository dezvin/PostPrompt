# Микроурок 23. Хуки: действие по событию

## Знакомый пример: напоминание о правилах общения

- В глобальном `AGENTS.md` сохранены правила общения
  - отвечать понятно и по делу
  - объяснять необходимое без лишнего усложнения
  - различать чатное сопровождение и создаваемые материалы
- Во время пятой практики показывалось сообщение
  - `Applying chat communication context`
- За этим сообщением стоит настроенный хук
  - при отправке пользовательского сообщения он запускает обработчик
  - обработчик возвращает короткое напоминание модели
- Зачем понадобилось напоминание
  - модель периодически переставала соблюдать правила общения
  - ответы снова становились сложными и перегруженными
  - хук добавляет напоминание без ручного повторения в каждом запросе

## Что такое хук

- **Хук**
  - настроенное действие, связанное с определённым событием в работе Codex
- Событием может быть
  - отправка пользовательского сообщения
  - предстоящий запуск инструмента
  - получение результата инструмента
- При наступлении события среда запускает заданный обработчик
  - например, локальный скрипт
  - для этого модели не требуется самой решить, что пора его вызвать
- Для работы хука нужны
  - включённая и разрешённая настройка
  - подходящее событие
  - доступный и исправный обработчик
- Механика описана в [официальной документации OpenAI о хуках](https://learn.chatgpt.com/docs/hooks)

## Постоянная инструкция и действие по событию

- **Постоянная инструкция**
  - сообщает модели, как работать
  - пример: отвечать понятно и соблюдать границу между чатом и материалом
- **Хук**
  - запускает конкретное действие в нужный момент
  - пример: добавить напоминание при отправке сообщения
- В нашем примере эти части работают вместе
  - полные правила находятся в `AGENTS.md`
  - хук передаёт короткое напоминание применить их
- Хук не заменяет сами правила
  - без понятного договора напоминанию не на что опираться
- Передача напоминания и соблюдение правил различаются
  - обработчик может успешно добавить текст в контекст
  - модель всё равно может ответить с нарушением правил
  - качество ответа проверяется отдельно

## Как работает наш пример

1. Пользователь отправляет сообщение
   - возникает событие `UserPromptSubmit`
2. Codex запускает разрешённый обработчик этого события
   - в нашем примере это скрипт с напоминанием
3. Обработчик возвращает текст
   - `Перед ответом примени к своей чатной части все относящиеся к ней правила из раздела «Personal Codex Communication Contract» глобального AGENTS.md, включая границу между чатной частью и создаваемыми материалами.`
4. Codex добавляет напоминание в контекст модели
   - через `additionalContext`
   - как дополнительную инструкцию
5. Модель готовит ответ с учётом полученного контекста

- Наш обработчик
  - возвращает только напоминание
  - не изменяет пользовательский запрос
  - не читает рабочие файлы
  - не отправляет сведения наружу
- Это свойства конкретного обработчика
  - другие хуки могут выполнять другие действия
- Передача дополнительного контекста подтверждена в [описании `UserPromptSubmit`](https://learn.chatgpt.com/docs/hooks#userpromptsubmit)

## Для чего ещё могут пригодиться хуки

- **При отправке сообщения**
  - событие `UserPromptSubmit`
  - добавить нужный контекст или напоминание
- **Перед запуском инструмента**
  - событие `PreToolUse`
  - проверить предложенную команду
  - при заданных условиях запретить поддерживаемый вызов
- **После получения результата инструмента**
  - событие `PostToolUse`
  - запустить проверку изменённого файла
  - вернуть сведения об обнаруженной ошибке
- Момент проверки влияет на результат
  - проверка до действия может предотвратить его
  - проверка после действия обнаруживает последствия
  - `PostToolUse` не отменяет уже выполненную операцию
- Возможности и ограничения этих событий описаны в [документации Codex](https://learn.chatgpt.com/docs/hooks#tool-coverage)

## Как поставить задачу на создание хука

- Сначала описать нужный результат обычными словами
  - какое повторяющееся действие хочется автоматизировать
  - в какой момент оно должно выполняться
- Определить границы
  - какие сведения обработчик может читать
  - может ли он изменять файлы
  - допустимы ли внешние обращения
- Попросить Codex предложить устройство хука
  - подходящее событие
  - действие обработчика
  - ожидаемый результат
  - способ проверки
- Пример запроса
  - `Я хочу, чтобы при отправке каждого моего сообщения Codex получал короткое напоминание применять правила общения из глобального AGENTS.md. Сначала проверь актуальную документацию и покажи, какое событие и обработчик предлагаешь использовать, что он будет делать и как проверить результат. До моего одобрения настройки не меняй.`
- После согласования выполнить настройку
  - сохранить существующие правила и хуки
  - проверить обработчик
  - просмотреть и разрешить новый хук
- Для знакомого примера уже есть отдельный материал
  - «Настройка понятного общения с Codex через глобальный `AGENTS.md` и хук»
  - полный порядок установки находится в этой инструкции

## Настройка создана и хук сработал

### Настройка создана

- В конфигурации указано нужное событие
- Зарегистрирована команда обработчика
- Файлы существуют и технически корректны
- Это подтверждает наличие настройки
  - ещё не подтверждает запуск при реальном событии

### Обработчик прошёл ручную проверку

- Ему передали тестовое событие
- Он вернул ожидаемое напоминание
- Это подтверждает работу обработчика на тестовом входе
  - ещё не подтверждает, что Codex вызывает его в диалоге

### Хук сработал в живом диалоге

- После настройки и разрешения открыт новый диалог
- Отправлено пользовательское сообщение
- Проверены фактический запуск и результат
  - обработчик успешно выполнился
  - напоминание добавлено в контекст
- Сообщение `Applying chat communication context`
  - помогает заметить активность хука
  - само по себе не доказывает успешное добавление напоминания

### Ответ соблюдает правила

- Проверяется обычный чатный ответ
  - понятность
  - прямой ответ
  - соразмерность вопросу
- Проверяется самостоятельный создаваемый материал
  - чатное сопровождение следует договору общения
  - сам материал соответствует своей задаче, читателю и форме
- Один удачный ответ
  - не доказывает срабатывание хука
  - не гарантирует соблюдение правил во всех следующих ответах

## Границы использования

- Перед разрешением хука нужно понимать его действие
  - какую команду он запускает
  - что читает и изменяет
  - передаёт ли сведения наружу
- Новый или изменённый пользовательский хук требует просмотра и разрешения
  - до этого Codex пропускает его запуск
  - доверие относится к конкретной редакции настройки
  - [Правила просмотра и разрешения хуков](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)
- Хук может завершиться ошибкой
  - наличие проверки не гарантирует остановку действия при её сбое
  - для защитного хука нужно отдельно проверить поведение при ошибке
- Хуки дополняют ограничения доступа и разрешения
  - не заменяют их
- Хук имеет смысл для конкретного повторяющегося действия
  - если достаточно обычной инструкции или разового запроса, отдельная автоматизация может не понадобиться
