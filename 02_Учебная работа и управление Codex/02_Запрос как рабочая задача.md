# Запрос как рабочая задача

## От запроса зависит работа Codex

- Запрос — это задача, которую человек передаёт Codex
- Главнее не идеальная формула промпта, а понимание
  - куда мы хотим прийти
  - что хотим получить
  - с чем предстоит работать
- Запрос можно формулировать обычными словами

## Если задача уже понятна

- Сказать, что нужно сделать
- Указать материалы, с которыми связана задача
- Не искать специальную или «правильную» формулировку
- Начать работу и уточнять задачу по мере необходимости

## Если мысль пока смутная

- Использовать микрофон и наговорить всё, что есть в голове
- Не пытаться заранее выстроить идеальную структуру
- Codex помогает
  - разобрать поток мыслей
  - выделить основную задачу
  - предложить понятную отправную точку
- Такой способ работы называется `rambling`

## Что может запустить запрос

- Ответ или объяснение
- Поиск и чтение материалов проекта
- Создание нового файла
- Редактирование существующего файла
- Помощь в уточнении самой задачи

## Работа с файлами проекта

- Сослаться на конкретный файл через `@`
- Либо попросить Codex самостоятельно найти нужный файл
- Использовать уже собранные в проекте материалы
- Не пересказывать содержимое файла, если Codex может его прочитать

## Без микроменеджмента

- Не расписывать Codex каждое действие
- Передать цель и необходимые материалы
- Не придумывать весь путь выполнения вместо инструмента
- Уточнять направление, когда появляется реальный результат

## Что показать

- Обычный короткий запрос своими словами
- Наговаривание смутной мысли через микрофон
- Как Codex превращает её в понятную задачу
- Обращение к файлу через `@`
- Просьбу самостоятельно найти нужный файл
